# 运行时报告与日志清理计划

## 目标

把 `reports/` 与 `logs/` 的运行期产物清理收敛到一个保守、可审计的白名单策略，并由每日主任务自动触发。

## 保留策略

| 范围 | 保留期 | 说明 |
| --- | ---: | --- |
| 日报、邮件报告、健康检查、调价报告 | 3 天 | 保持现有邮件侧策略 |
| MI 快照 | 30 天 | 保持趋势分析需要 |
| Terapeak、CRO、compare、普通 audit/reprice/dropship 报告 | 30 天 | 运营排查窗口 |
| 关键整改、恢复、删除/重刊核验、关键审计产物 | 180 天 | 保留追责和回滚依据 |
| 带日期的普通日志 | 30 天 | 日常运行排查窗口 |
| 带日期的关键审计/恢复/故障日志 | 180 天 | 长期证据 |
| 无日期、状态文件、数据库、密钥、图片及不支持扩展名 | 不自动删除 | 降低误删风险 |

## 执行方式

1. `src/utils/report_retention.py` 负责规则、日期解析、候选发现和删除。
2. `scripts/report_retention.py --dry-run` 只输出候选，不删除（省略参数时也默认为 dry-run）。
3. `scripts/report_retention.py --apply` 执行白名单删除。
4. `daily_tasks.py` 每日主流程开始时自动执行一次实际清理；单个文件失败不阻断主任务。
5. 清理依据文件名中的日期，不使用 mtime 猜测无日期文件；未登记但带日期的常规文本产物走 30 天安全兜底。

## 验收标准

- 不符合专用规则、安全兜底或日期解析要求的文件保持不变。
- dry-run 不产生删除。
- apply 只删除已过保留期的候选，保留近期文件。
- 清理异常记录日志并继续处理其他文件。
- 现有测试与清理模块测试通过。
